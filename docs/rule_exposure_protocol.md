## 问题与非主张

在始终提供当前动态参数的前提下，逐模块混合稳定流程说明是否比整段混合或
短提示专项训练更能保留新政策条件下的决策能力？
这不是证明退火次序更好，不是首次内化规则，也不声称模型能猜测未提供的政策。

该设置是新写的模拟 refund 规则任务，不等同历史 refund gold、不等同 ABCD，
也不使用原有 MBPP/ABCD 测试或修改它们的结论。结构化事实直接提供给模型。
规则引擎可精确求解，所以本轮没有理由声称比“结构化事实＋程序”更适合部署。
后续如主张自然语言业务价值，必须加入抽取＋规则引擎等实际系统对照。

相关工作已研究政策内化和替换/覆盖，本协议并不把这个话题本身称为新颖：
[CAP-CPT](https://aclanthology.org/2026.acl-long.767/)；
完整主张需要方法对照和独立验证，不能仅靠新名称。

## 规则和数据

五个有明确优先级的稳定模块：风险转人工 → 信息缺失 → 质量/证据 →
特殊商品资格 → 普通退货条件。代码中的 MODULES 与 decide 是完整规范。
动态参数只有 return_days、review_amount、customized_allowed，所有训练/评估
提示都明确提供全部三个当前值；不使用含糊的增量 patch、版本路由或安全政策覆盖。

训练政策：基础 (7,1000,false)，以及分别把期限改为14、金额门槛改为1500、
定制资格改为true 的三个单变化版本。评估政策：

| 类型 | return_days | review_amount | customized_allowed |
| --- | ---: | ---: | --- |
| 原政策 | 7 | 1000 | false |
| 未见组合 | 14 | 1500 | true |
| 未见取值 | 10 | 1250 | false |
| 未见取值 | 21 | 750 | true |

案例来自固定枚举空间，按基础规则的五种决策分层抽取，固定随机种子，先划分
128 train/48 eval 结构化事实，再展开政策与提示；完全相同的事实不能跨 split。
这是为了诊断而设的近似均衡分布，不是自然业务发生率，也不是隐藏 benchmark。
评估参数取值及组合未用于训练，但它们是预先写在协议里的有限固定集合。

## 四组匹配设计

- Full-only：每条提供全部五个稳定模块。
- Short-only：不提供稳定模块说明，但任务/标签定义和当前参数仍保留。
- Whole-mix：固定种子打乱，一半记录提供全部模块、一半不提供。
- Component-mix：每个模块恰好出现在一半记录；各模块独立打乱掩码。

两种混合组每个模块的总曝光次数完全相同，区别在模块是否共同出现。
掩码不依据案例标签、难度或模型表现选择。不是按答案有针对性地给提示。
所有组业务样本/政策/标签/输入顺序相同。一个新 LoRA seed，同一基础模型，
rank16/alpha32/dropout0，batch1 × accumulation8，512 条记录完整一遍、64 updates，
AdamW、LR1e-4、线性衰减、无 warmup/weight decay、最大梯度范数1。
无 packing、重排或超长删除；实际模板超长在训练前停止。
每组起始可训练 LoRA 张量哈希必须相同，固定最终 checkpoint，不看分数选择。
回调记录实际更新步数与权重变化；没有声称完整复刻旧精确 token 消费审计。
总模块次数相同不等于 token/FLOPs 完全相同，预检分别记录真实训练 token 总量。

## 评估和统计

同一48案例 × 4政策 × Full/Short = 每端点384条；基础模型仅评估一次，加4组
训练端点，共1920次单样本生成。greedy，关闭思考，max_new_tokens48，最长2048。
模型输入只传 messages，不传 target；预测按稳定 id 对齐，不按文件行号猜对应。
主评分仅接受唯一 decision 键的合法 JSON（允许框架的空 think 前缀），非法格式
计错，不做“挑最合理 JSON”式修复，不重试失败答案。

主要探索对比：Component-mix 对 Whole-mix、Short-only 的 Short 未见取值准确率差。
完整报告 Full-only 及基础模型，不隐藏不利结果。补充原政策、未见组合、修改影响
案例准确率、未受影响案例准确率、原本正确案例上的误伤率、修改前后同时正确率、
格式有效率、实际输入 token。无适用样本时指标为 null 并给分母。
配对区间以 case 为单位重采样，保留同一 case 的政策版本关系，2000次、固定seed。
一条案例的多个版本不是多个独立案例；单seed区间不覆盖训练随机性或政策总体。
记录逐请求时间，但包含首次请求且无正式延迟基准，不据此宣称生产吞吐或等比例加速。

## 运行与停止

每个 worker 最多2小时，整个 campaign 累计最多8小时；总共四个训练任务，
不并行抢占多卡。最多两个显式尝试/阶段，失败扣预算，完整结果只在全部阶段通过后汇总。
结构化输出低分、对比不显著不触发自动重跑。该探索可以失败或无优势。
CPU simulate 使用 oracle 假预测，只验证工程链路；报告标明 SIMULATION，不是科学证据。

研究后续由结果决定：有值得追的信号再设计独立种子、规则版本和自然语言任务。
